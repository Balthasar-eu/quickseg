# Quickseg

[Read the preprint here!](https://www.biorxiv.org/content/10.64898/2026.08.31.747916v1)

Quickseg is a fast copy number segmentation tool for binned sequencing read counts.

It segments genomic read depth into regions of constant copy number using a dynamic programming approach optimized for large datasets. Input is provided as BED-like TSV files containing genomic intervals and read counts, such as those generated by `mosdepth` or `samtools`.

The software is written in Rust and includes AVX2 and AVX-512 optimized implementations for high-performance segmentation of whole-genome data.

## Features

- Fast dynamic programming based copy number segmentation
- Supports any dataset in bed format with human chromosomes
- Optional normalization against a matched normal sample
- Automatic normalization based on the global median
- SIMD acceleration (AVX2 or AVX-512 when available)
- BED-like output format

## Installation

Clone and build from source:

```bash
git clone https://github.com/Balthasar-eu/quickseg.git
cd quickseg
cargo build --release
```

The executable will be available at:

```bash
target/release/quickseg
```

## Input format

Quickseg expects a tab-separated BED-like file with four columns:

```text
chromosome    start    end    count
```

Example:

```text
chr1    0        10000    102
chr1    10000    20000    98
chr1    20000    30000    101
```

Files generated by `mosdepth` are suitable input.

## Usage

```bash
quickseg --input counts.bed --output segments.bed
```

### With a matched normal sample

```bash
quickseg \
    --input tumor.bed \
    --normal normal.bed \
    --output segments.bed
```

### Save normalized counts

```bash
quickseg \
    --input counts.bed \
    --output segments.bed \
    --normalout normalized.tsv
```

## Command Line Options

### Input and Output

#### `-i, --input <FILE>`

Input file in BED-like TSV format.

The file must contain four columns:

```
chromosome    start    end    count
```

The fourth column must contain integer read counts. Output generated by tools such as mosdepth can be used directly.

#### `-o, --output <FILE>`

Output file containing segmented copy number regions.

#### `--normalout <FILE>`

Write the normalized values that are used internally for segmentation.

This can be useful for plotting, debugging, or investigating unexpected segmentation results.

#### `--normal <FILE>`

Optional matched normal sample.

When provided, counts are normalized against the normal sample before segmentation.

#### `--median <MEDIAN>`

Expected value range of the inputdata.

The value needs to be greater than the median of the input data. For targeted panel or amplicon sequencing, a larger value may be required, but for WGS the default should be appropriate. This value only affects runtime and memory consumption of the initial data-loading. If the median exceeds it, however, the program will fail.

Default:

1000

#### `--penalty <PENALTY>`

Penalty parameter controlling the number of segments.

Lower values generate more segments and capture smaller changes.

Higher values generate fewer segments and produce smoother segmentations.

Default:

10

#### `-h, --help`

Display the help message.

#### `-V, --version`

Display version information.


## Note

Quickseg optimizes each segment to its median value. For segments containing an even number of observations, multiple median values may yield exactly the same optimal score.

As a result, different implementations (scalar, AVX2, and AVX-512) may occasionally report different segment values when several equally optimal medians exist. The segmentation itself and the associated optimization score remain unchanged, and all reported solutions are equally valid.
